# User Manual

## Visiting the portfolio

Open the deployed site in a supported browser. The portfolio presents the main areas in this order:

1. Home/About — background and positioning.
2. Projects — selected work and project details.
3. Activities — talks, hackathons, and community activity.
4. Contact — public contact links and resume download.

Use the section navigation to move between areas. On smaller screens, the site uses conventional vertical scrolling; on larger screens, sections may use the presentation-style horizontal layout.

## Changing language

Use the language selector to switch between the locales exposed by the current implementation. The selected locale is reflected in the route and the site falls back to the configured default when a translation is unavailable.

## Opening projects and media

Select a project card to view its available details, technology information, links, and media. Only links and media that have been published in the repository are expected to be available.

## Using the portfolio assistant

1. Open the chat launcher.
2. Enter a question about the portfolio owner’s documented projects, activities, experience, or FAQ.
3. Submit the question and review the answer and source information.
4. Treat an unavailable/provider-configuration message as a service issue rather than repeatedly submitting sensitive information.
5. Do not enter passwords, API keys, private documents, or other sensitive information.

The assistant is designed to answer from portfolio documentation. It may say that it does not have information when a question is outside the available documents.

## Downloading the resume

Use the resume link in the Contact area. If the file does not open, record the deployed URL, browser, and response status for the maintainer.

## Accessibility and browser use

Use keyboard navigation and visible focus states. Respect reduced-motion settings. Report missing labels, inaccessible controls, layout failures, console errors, or browser-specific differences with the browser name, version, URL, steps, and expected result.

## Reporting an issue

Before reporting, record:

- Page and locale URL.
- Browser and operating system.
- Steps to reproduce.
- Expected and actual behavior.
- Screenshot or console/network error when safe to share.
- Whether the problem is reproducible after a refresh.

Do not include credentials, private user data, or full environment files in an issue.
